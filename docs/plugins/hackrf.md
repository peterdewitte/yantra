# Plugin: hackrf (HackRF One)

`hackrf.so` (plugin id `hackrf`, RAD-60): the HackRF One through the
built-in SoapyHackRF module and libhackrf, with HackRF gain presets, offset
tuning, band scans and optional C1. The shared SoapySDR layer is described
in [RADIO_PLUGINS.md, the SoapySDR plugins](../RADIO_PLUGINS.md#the-soapysdr-plugins-rad-54-rad-62)
and [the HackRF plugin](../RADIO_PLUGINS.md#the-hackrf-plugin-rad-60); the
test tool is [yantra-hackrf](../YANTRA_HACKRF.md). Capabilities HOTPLUG
and SCAN. Hardware results: [DEVICES.md](../../DEVICES.md).

## Devices

Every HackRF the module finds, key `hackrf:<serial>`, stable across
replugs. Linux needs the udev rules of `udev/60-yantra-sdr.rules`
(installed to `lib/udev/rules.d`); without access the device is listed
with the remedy.

## Records

`tetra_cell`, `tetra_neighbour` and `tetra_scan`, levels in dBFS
(the plugin is not SELF_CALIBRATED; Yantra calibrates per gain
combination). With `c1_enabled` and `c1_level_offset_db` the records
get `c1_db`. Fields: [TETRA_RECORDS.md](../TETRA_RECORDS.md).

## Known issues

- Not yet measured on real hardware: the calibration offset, level
  linearity (RAD-125) and the HackRF rows of DEVICES.md stay open until
  `yantra-hackrf report` has run on a HackRF One.
- The LO sits 250 kHz (`offset_khz`) away from a single carrier, so the
  DC spike stays out of the channel.
- The HackRF has 8-bit samples: keep the LNA/VGA gains so that
  `clipped_percent` stays 0 near a site (preset `near_site_strong`).
