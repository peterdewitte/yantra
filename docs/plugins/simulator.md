# Plugin: simulator (Demo, simulated network)

`simulator.so` (plugin id `simulator`, RAD-61): a simulated TETRA
network, for demos, training and tests without a radio. Capabilities
SIMULATED, SCENE and SPECTRUM (a synthetic spectrum of its scene, radio
API 1.2, RAD-140). How it works (scenarios, positions, calibration
practice, real time): [RADIO_PLUGINS.md, the simulator plugin](../RADIO_PLUGINS.md#the-simulator-plugin-rad-61).

## Devices

One device, `simulator:0` "Demo (simulated network)", always present,
with the flag LEVEL_DBM while the setting `level_unit` (Levels) is
`dbm` (the default; radio API 1.1, RAD-30).

## Records

`tetra_cell` and `tetra_neighbour` with `simulated` set: levels in dBm
(calibrated, flag LEVEL_DBM, never UNCALIBRATED) by default, or in dBFS
like an SDR with Levels `dbfs` (the plugin is not SELF_CALIBRATED; the
schema's level unit says dBFS, RAD-21); the `sim_position` group when a
position is known, and the generator's own fields (`cell_id`,
`level_inst_dbm`, `level_source`, `best_antenna`, `walls`); every field
in [TETRA_RECORDS.md](../TETRA_RECORDS.md). Every record has the
SIMULATED flag.

## Known issues

- Without a floor plan, a scene (`get_scene` NOT_FOUND, a user's own
  floor in Yantra 0.4; one INFO log line per plan, no warning) or a
  position the levels are the scenario's own (fixed per cell), not the
  multi-wall model.
- The bundled scenarios assume the example ids `fraunces-*`,
  `mak-beer-house-*`, `mak-haus-claeson-*` and `mak-villa-bunzl-*`
  (owner question: which ids Yantra sends).
- Under sanitizers or on a slow computer the simulation runs slower than
  real time (sensor `receiver_load` above 1); nothing is dropped. The
  time base moves with the lag when an interval starts, where the
  position is read: a record's time is when its sim_position was taken,
  so a slow interval's records reach the host late (by up to the
  interval's processing time) rather than with a later time than their
  position's.
